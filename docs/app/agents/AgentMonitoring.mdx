## Managing Hosts

For environments using the [Gateway architecture](./Agent#gateway-architecture), Hosts are the PCs where Gateway executables are installed. The **Connectors > Hosts** page allows you to view and manage all Hosts in your environment.

### Viewing Hosts

Navigate to **Connectors > Hosts** to see all Hosts in your environment. The buttons above the table show how many Hosts are in each status. Click a status button to filter the table to that status, or click **Total** to clear the filter.

The Hosts table has the following columns:

- **Host Name**: The name assigned during Gateway installation. Click the name to open the Host's detail page.
- **Machine Name**: Hostname of the machine the Host runs on
- **Connections**: Number of Connections on the Host. Click the button to open the Connections page filtered to this Host.
- **Started at**: Time when the Host was first registered in Ganymede
- **Last Status Ping**: Time when Ganymede last received a status ping from the Host
- **Status**: Current status of the Host
- **Gateway Version**: The version of the Gateway running on the Host

#### Host Status

Hosts send a status ping to Ganymede every 30 seconds. A Host can have one of the following statuses:

- **Live**: The Host is running and can communicate with Ganymede.
- **Updating**: The Host is upgrading to a new Gateway version. A Host moves to Updating as soon as an upgrade is triggered.
- **Error**: The Host is in an error state and needs user intervention. Connections on the Host show as **Failing**.
- **Disconnected**: Ganymede has not received a status ping from the Host in the last 65 seconds. A Host that stops processing for 15 minutes also shows as Disconnected and, when installed as a service, restarts itself.
- **Shutdown**: The Host is inactive because the host PC was shut down or is asleep, or the Host service was stopped.
- **Deprecated**: The Host is inactive because it was disabled or deleted.

To delete Hosts that are no longer in use, select them in the table and click **Delete Host**. Live Hosts can't be selected. See [Removing Hosts](#removing-hosts).

### Host Details

Click a Host to open its detail page. The page contains:

- **Host Settings**: The Host's details, labels, and email alerts. See [Host Details](#host-details-1) for the fields.
- **Core Host Infrastructure**: The Gateway version the Host is running and an **Upgrade** button when a newer version is available. While an upgrade runs, a banner at the top of the page shows the old and new versions. If an upgrade fails, the panel shows the version the Host rolled back to, and you can click **Upgrade** to try again. See [Updating Hosts](#updating-hosts).
- **Deployment Settings**: Choose whether code and configuration changes deploy automatically to Live Connections, or require re-installing executables to take effect.
- **Stop Host Service**: Click **Stop Service** to stop the Host service on a Live Host. All Connections on the Host stop running. To restart or fully uninstall the Host service, do so on the machine where the Host is installed.
- **Connections**: All Connections on this Host
- **Host Metrics Charts**: CPU, memory, and disk usage of the host PC over the last 24 hours
- **Logs**: Streaming and stored logs for the Host. See [Viewing Logs](#viewing-logs).

### Creating Connections on a Host

1. Navigate to the Host's detail page
2. Click <div className="button dark_gray_button"><PlusOutlined /> Create Connection on Host</div>
3. Choose one of the following options:
   - **Create from Template**: Select an Agent Template and configure a new Connection
   - **Move Existing Connection**: Migrate a Connection from another Host to this one

For OPC-UA Subscription Agent Templates, create the Connection from the Host's page as described here. See [OPC-UA Subscription Agents](./OpcUaSubscription#create-a-connection-on-a-host).

### Moving Connections Between Hosts

To move a Connection from one Host to another:

1. Navigate to the destination Host's detail page
2. Click <div className="button dark_gray_button"><PlusOutlined /> Create Connection on Host</div>
3. Select **Move Existing Connection**
4. Choose the Connection to move from the list
5. Wait for the migration to complete

The Connection will stop on the source Host and start on the destination Host. No data is lost during the migration.

### Updating Hosts

Hosts running Gateway version 5.6.0+ can be updated through the Ganymede UI:

1. Navigate to the Host's detail page
2. If an update is available, an **Upgrade** button will appear
3. Click **Upgrade** to update the Host to the latest Gateway version
4. All Connections on the Host will be updated simultaneously

:::note

A Gateway that runs without admin privileges can't be upgraded from the Ganymede UI. The **Core Host Infrastructure** panel shows **Updates must be applied manually**, and the **Upgrade** button is disabled. To upgrade, download the new version and run the installer manually on the host machine.

:::

### Removing Hosts

To remove a Host:

1. Move or delete all Connections on the Host
2. Uninstall the Gateway from the PC using the standard uninstallation process
3. Once the Host is no longer Live, go to **Connectors > Hosts**, select the Host, and click **Delete Host**. This action can't be undone.

### Updating Agents

To modify an Agent Template after creation, select it on the **Connectors > Agent Templates** page and update its configuration. Upon clicking <div className="button darkblue_button">Save</div>, the changes to the Agent Template will be applied to any running Connections based on that Agent Template.

Agent Templates can also be archived, disabled, or deleted. Use the links below the Connections table on the Agent Template's page:

- **Archive Agent Template**: Archived Agent Templates can't be modified, but all associated Connections continue to run. To make an archived Agent Template active again, click **Restore Agent Template**.
- **Disable Agent Template**: Available for archived Agent Templates. Disabled Agent Templates can't be modified, and all associated Connections are moved to the Deprecated state. To make a disabled Agent Template active again, click **Re-enable Agent Template**.
- **Delete Agent Template**: Available for disabled Agent Templates.

#### Updating Connections

Every time the Connection contacts Ganymede with a health check-in, Ganymede responds with any changes that the Connection needs to incorporate. There are three level of changes that can occur.

- **Core Version Update**: The core version corresponds to the underlying Host code developed by Ganymede. These changes are new features or patches applied across all Connections, but each Host manages which core version it is pinned to.
- **Agent Template Update**: Updated through the Agent Template page or the Agent Template's processor notebook. This configuration applies to all Connections for that Agent. For example, if an Agent that runs flow upon file capture is updated to run a new flow, then all compatible Connections will begin to run the new flow.
- **Connection Configuration Update**: Updates made to the Connection's configuration will only update a single Connection, rather than the Agent Template that it was generated from. Different Connection-level variables and labels can be configured for Connections associated with the same Agent Template.

There are two types of remote updates that occur based on the type of update - full update or runtime update.

#### Full Update

**Compatibility**
- Agents or Hosts running core v4.8.0 or later.
- The core version of the installed connection must align with the major version of the core version of the agent Ganymede's UI. Otherwise, a breaking change requires reinstallation.
- For Hosts, the Host's **Deployment Settings** are set to **Auto deploy code and configuration changes to Live Connections**. For legacy Agents, auto-update is enabled for the Agent.
- For Hosts, the Gateway runs with admin privileges. See [Updating Hosts](#updating-hosts).

##### How full updates are initiated

A full update is only triggered for a "Core Version Update." The remote update is not initiated without user intervention. 

:::note

In the Ganymede UI, a Host's core version is listed on the right side of the page in a section called "Core Host Infrastructure." If the host is not up to date to the latest available core version, an "Upgrade" button will appear. The text will inform users what version is available and what version the host is currently pinned to. 

:::

Once a user clicks to Upgrade an host, the host will update on its next status ping.

##### Update Process

A full update is handled by Ganymede seamlessly; as such, after the full update is requested, it is performed for the Host. When Host receives a command to perform a full update, it continues to operate normally while attempting to start the new version in parallel after verifying the validity of the command and the executable. Once the new version registers with Ganymede as operational, the old Gateway stops. The new executable also cleans up the artifacts of the old executable and its dependencies.

There may be a disruption to any ongoing processing on the Agent during the update, so it is safest to request it when no activity occurs on the instruments where the Agent Connections are running.

If the new Gateway fails to start, the old Gateway will resume, and the system will not attempt a full update again on that version to avoid putting the Host in a precarious state.

#### Runtime Update

##### Compatibility

- Agents _installed_ with core v1.0.0 or later
- The core version of the installed connection must match the core version of the agent Ganymede's UI
- For Hosts, the Host's **Deployment Settings** are set to **Auto deploy code and configuration changes to Live Connections**. For legacy Agents, auto-update is enabled for the Agent.

##### How runtime updates are initiated

Changes in the Agent Template configuration, including the Agent user-defined code, or Connection configuration, will be sent to the Connection on its next status ping as soon as they are saved.

##### Update Process

A runtime update does not require any process restart or executable reinstallation. As a result, the Connection can accept changes to configuration while continuing normal operations. The update is validated for integrity and the information is stored locally for access if the Connection restarts for any reason.

Below the Connection Details box, the **Connection Settings** panel contains Connection-specific configurations. Click **Edit Connection** to change them:

- **Image**: The image shown for the Connection. By default, this is the Agent Template's image. To use a different image, click **Upload Custom Image** while editing.
- **Name**: Display name used to identify the Connection. It is required, can be up to 255 characters, and doesn't have to be unique across Connections or within a Host.
- **Trigger settings**: Settings that depend on the Agent Template's trigger. For file watcher Agent Templates, these are **Input Path**, **Ignore Patterns**, **Stable Time (seconds)**, **Stream Contents**, **Ignore Hidden Files**, and **Ignore Hidden Directories**. See [Reserved variables for File Watcher Agents](./Agent#reserved-variables-for-file-watcher-agents). For OPC-UA Subscription Agent Templates, see [OPC-UA Subscription Agents](./OpcUaSubscription).
- **Connection File Tags**: [Tags](../files/Tags.mdx) placed on files uploaded by the Connection
- **Variables**: [Key-value pairs](./Agent#variables-and-labels-in-windows-agent-connections) that can be referenced in user-defined code.  These are also used to specify [reserved keywords](Agent#reserved-variables-for-all-agents) for the Connection, if applicable.
- **Labels**: [Strings](./Agent#variables-and-labels-in-windows-agent-connections) that can be used to group Connections in the Ganymede UI
- **Emails**: Email addresses to notify when the Connection encounters an error.  These email addresses are also used by the [notify function found in the `agent_sdk`](../../sdk/markdowns/AgentSDK#notifications).

### Connection Status

A Connection's status combines its own state with the status of the Host it runs on (see [Host Status](#host-status)). The Connections page shows how many Connections are in each status. A Connection can have one of the following statuses:

- **Live**: The Connection is running and can communicate with Ganymede.
- **Failing**: The Connection is running but not working properly. For example, an internal thread failed, the watched directory is missing or not mounted, or the Host is in an Error state. The Host restarts failed threads automatically, and the Connection returns to **Live** once the watched directory is available again. See [Agent FAQ and Troubleshooting](./DebuggingAgents) for troubleshooting tips.
- **Disconnected**: The Connection's Host can't communicate with Ganymede. Ganymede has not received a status ping from the Host in the last 65 seconds, or the Host stopped processing for 15 minutes. When the Host is installed as a service, it restarts itself after a 15-minute stall.
- **Shutdown**: The Connection runs on a Host that was shut down.
- **Deactivated**: Processing for the Connection was turned off with **Disable Connection** in the Connection State panel on the Connection's page. Click **Activate Connection** to turn it back on.

### Deactivating and Deleting Connections

To stop a Connection without deleting it, open the Connection and click **Disable Connection** in the **Connection State** panel, then confirm. The Connection no longer runs or processes data, and its status changes to **Deactivated**. To resume processing, click **Activate Connection**.

You can delete Connections that you no longer use. Only Disconnected, Shutdown, or Deactivated Connections can be deleted. On the **Connectors > Connections** page, click the delete icon on the Connection's card and confirm. You can also delete these Connections from the Connections table on an Agent Template's page. Changing a Connection's state or deleting it requires Writer access.

### Connection Notifications

For Agents v5.1.7+, you can create send email notifications to all subscribers by using the `agent_sdk.notify` method in your user-defined processor code. For example:

```python
import agent_sdk

def execute(**kwargs) -> Optional[TriggerFlowParams]:  # type: ignore
     # ... code here that checks for some condition
    if(some_condition):
        agent_sdk.notify(f"The file {file_name} is missing an experiment ID")
```

### Viewing Logs

Logs are in the **Logs** section of each Host's detail page, which has two tabs:

- **Streaming**: Logs from the Host and all of its Connections, updated as new logs arrive
- **Stored**: Daily log files you can download, so you can search over logs locally. For each date, click the **Console Log** or **Event Log** link to download that file.

Each Connection's page also shows a streaming log table filtered to that Connection.

To narrow down streaming logs, use the filters above the table:

- **Search Message**: Text to search for in log messages
- **Connection**: The Connection that wrote the log (Host page only)
- **Log Levels**: One or more of Error, Activity, Info, and Debug
- Date range

Click **Search** to apply the filters, or **Reset Filters** to clear them. Log streaming pauses while filters are active. Use **Search** or **Reset Filters** to get the latest logs.

Up to 10K logs are fetched at a time, so apply filters to refine your search. The **Context** column shows the Host and Connection that wrote each log. Long messages are cut off in the table. Expand the row to read the full message, up to 10,000 characters.

For Agents v4.9+, user-defined log messages can be added by referencing the corresponding [`agent_sdk` method for logging](../../sdk/markdowns/AgentSDK#logging-methods). Descriptions of log messages can be found on the [Agent Logs page](./AgentLogs).

### Host Details
Host data can be viewed by clicking on the Host from the listing page or the Host chip.

| Field Name | Description |
|------------|-------------|
| Host Name | Display name used to identify the Host |
| Status | Current running status of the installed Host. See [Host Status](#host-status). |
| Gateway Version | The version of the core Host infrastructure (Gateway) the Host is running |
| Runtime Version | The version of the Host configuration currently running |
| Started at | Time when the Host was first registered in Ganymede |
| Last Status Ping | Time when Ganymede last received a status ping from the Host |
| Install Path | Directory path on the hosting machine where the executable was installed |
| Service Name | The operating system's service name for the Host on the hosting machine |
| Machine Name | Hostname of the machine the Host runs on |
| Machine IP | IP address that Ganymede sees from the machine the Host runs on |
| Machine Architecture | Processor architecture of the hosting machine |
| Operating System | Operating system of the hosting machine |
| Running as User | The account username the Host is running as |
| Timezone | Time zone of the hosting machine |
| Clock Drift (s) | Difference in seconds between the hosting machine's clock and Ganymede's servers, measured when the Host starts |

Fields without a value are hidden.

- **Emails**: Email addresses that receive Host status and resource usage alerts.  These email addresses are also used by the [notify function found in the `agent_sdk`](../../sdk/markdowns/AgentSDK#notifications).
    - *Send Host Status Email Notifications*: When enabled, Ganymede sends an email when the Host becomes disconnected or comes back online. See [Host Status](#host-status).
    - *Host Offline Alert Timeout (min)*: The number of minutes to wait after the Host is determined to be offline before sending an alert email. The minimum is 5 minutes.
    - *Send Email Notification on Host Shutdown*: When enabled, Ganymede also sends an email when the Host enters the Shutdown state.
    - *Send Resource Usage Alerts*: When enabled, Ganymede sends an email when the Host's disk, CPU, or memory usage stays at or above its threshold for the resource usage alert window. These alerts are independent of the disconnect and shutdown alerts and go to the same email addresses.
        - *Disk Usage Alert Threshold (%)*, *CPU Usage Alert Threshold (%)*, and *Memory Usage Alert Threshold (%)*: The usage percentage, a whole number from 0 to 100, that triggers an alert for each metric. Leave a threshold empty to skip alerts for that metric.
        - *Resource Usage Alert Window (min)*: How long usage must stay at or above a threshold before an alert is sent. The default is 15 minutes and the minimum is 5 minutes. This field is required when any threshold is set.

  Resource usage alerts ignore brief spikes. After an alert, the same metric doesn't alert again until usage stays below its threshold for about half the window. Usage isn't checked while the Host is updating or offline. If several metrics cross their thresholds at the same time, you get one email that lists all of them.


## Uninstalling Agent Connections

### Windows

A Host can be uninstalled and its associated service removed through the “Add or Remove Programs” panel from the Control Panel.

<div class="text--center">
  <img
    alt="Agent uninstall"
    src="https://ganymede-bio.mo.cloudinary.net/agent/Agent_Uninstall20230615.png"
    width="500"
  />
</div>
&nbsp;

After uninstalling the Gateway, the Ganymede folder will remain in the Program Files directory. You can also run the `unins000.exe` file in the installation folder to remove the Gateway and all other previously installed versions.

:::warning

By default, the installation directory of the Gateway is retained, so that logs associated with the Gateway are kept on the instrument PC.  Removing the Ganymede folder will also remove these logs.

:::

:::info

If the Gateway service continues to appear in the Services panel after uninstalling the Gateway, you can remove it by running the following command in the Command Prompt:

```bash
sc delete <service_name>
```

:::

### Linux

To uninstall the Gateway, stop the systemd service associated with the Gateway and remove the service file from /etc/systemd/system/.

Replace `<service_name>` with the **Service Name** shown on the Host's detail page.

```bash
# stop the Gateway service
sudo systemctl stop <service_name>.service

# remove the service file
sudo rm /etc/systemd/system/<service_name>.service
```
