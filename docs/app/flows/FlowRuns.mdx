The **Flow Runs** page, at **Flows > Flow Runs** in the left navigation, contains the current status of different Flow runs that have been executed.  To view historical runs for a specific Flow, select the Flow from the datalist in the header.

To download or obtain more information about an input or output file, click on the file name. This will open a pop-up allowing you to get a link to the file, download the file, or view additional details about the file.

### Observing Flow Status

When no Flow is selected, the page shows a **Flow Runs Last 7 Days** chart that summarizes recent Flow runs across the environment.

The run status table displayed consists of the following columns:

- **Input File**: Input files and input parameters associated with Flow run.
- **Output File**: Output files (if applicable).
- **Run By**: Who or what triggered the Flow run, such as a user, an agent, or a cron schedule. You can filter this column by Connection.
- **Run Tag**: Run Tags associated with the Flow run.
- **Flow Run ID**: ID unique to each execution of the Flow. Two Flow runs from different Flows can have the same ID.
- **Start Time**: Timestamp of when the Flow was initiated.
- **Duration**: How long the Flow run ran.
- **Status**: The current status of the flow run instance. You can filter this column by status. Clicking the status opens the run logs. Possible status values include:
  - **Queued**: The Flow run is waiting to start.
  - **Running**: Job is in the process of running.
  - **Success**: All Nodes have run successfully.
  - **Validation Error**, **Connection Error**, or **Function Error**: At least one Node failed, and the status names the [error type](./FlowView.mdx#error-attribution) of the failure. If Nodes in the same run fail with different error types, Validation takes precedence over Connection, and Connection over Function.
  - **Platform Error**: The Flow run failed and no error type was recorded for the failure.
- **Logs**: Opens the [**Flow Run Logs**](#observing-node-status) drawer for the run. For failed runs, the link reads **Error Logs**.
- **Flow Version**: The version of the Flow that ran. See [Determining what code ran](#determining-what-code-ran).

### Observing Node Status

Clicking a run's status or its **Logs** link opens the **Flow Run Logs** drawer. The drawer has two panes:

- **Node Status**: Lists each Node in the run with a status chip. Click a Node to display its logs. If the Flow has an owner, the owner's contact is shown below the list.
- **Node Logs**: Shows the logs for the selected Node. If the Node raised an error, the error message, line number, and function appear at the top of the logs.

Node status chips include:
  - **Success**: The Node completed successfully.
  - **Running**: The Node is currently running.
  - **Queued**: The Node is awaiting system resources to start.
  - **Up for retry**: The Node failed on at least one try and is awaiting a retry.
  - **Upstream failed**: A dependency for the Node failed, preventing this Node from being run.
  - **Skipped**: The Node was skipped before completion. This may indicate a system resource limitation.
  - **Validation Error**, **Connection Error**, or **Function Error**: The Node failed, and the chip names the [error type](./FlowView.mdx#error-attribution) of the failure.
  - **Platform Error**: The Node failed and no error type was recorded for the failure.

You may also see **Scheduled**, **Up for reschedule**, **Deferred**, **Removed**, **Restarting**, or **None**.

The logs show the most recent entries, so the error messages and tracebacks from a failed Node are visible. If a log is too long to show in full, the drawer says so and shows only the most recent lines. To get the full output, click **Download complete log**. If the Node was retried, each attempt can have its own download button, labeled with the attempt number. Downloads are available for runs of Flows saved or deployed after the October 08 2026 release. For older runs, the drawer says that the complete log isn't available for the run.

Older runs whose execution details have expired show no Nodes in the drawer.

### Determining what code ran

Flow runs include a link to a Flow Version, indicating which version of the Flow was executed for the given run.
